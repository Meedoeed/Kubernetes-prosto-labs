# Как помочь серии

Исправления опечаток, уточнения команд и отчёты о проблемах помогают сделать лабораторные воспроизводимыми.

## Сообщить об ошибке

Перед созданием Issue посмотрите [диагностику](docs/troubleshooting.md) и существующие обсуждения. Если подходящего случая нет, создайте Issue с таким содержанием:

```text
Лабораторная и шаг:
ОС и архитектура компьютера:
WSL2 / Docker Desktop / Docker Engine:
Версия Docker:
Версия kind:
Версия kubectl:
Версия Kubernetes, если кластер запустился:

Что выполнял:
Что ожидал получить:
Что получил:
Полный текст команды и ошибки:
Что уже проверил:
```

Версии можно получить командами:

```bash
docker version
kind version
kubectl version --client
kubectl get nodes
```

Если последняя команда не работает, приложите её ошибку. Сообщения терминала лучше отправлять текстом в блоке кода; скриншот можно добавить как дополнение. Не публикуйте kubeconfig целиком, токены, пароли и приватные адреса из рабочих окружений.

## Предложить исправление

1. Создайте fork и отдельную ветку для изменения.
2. Исправьте конкретную проблему, сохраняя объём тем соответствующей лабораторной.
3. Проверьте относительные ссылки и оформление Markdown.
4. Если меняются команды, по возможности выполните затронутые шаги и укажите проверенное окружение. Если запуск не выполнялся, прямо напишите об этом.
5. Откройте Pull Request: опишите проблему, изменение и способ проверки.

Для опечатки достаточно небольшого PR без прогона кластера. Для нового раздела сначала удобно обсудить идею в Issue.

## Принципы материалов

- Лаба закрепляет соответствующую теоретическую статью; новые понятия вводятся только при необходимости.
- У шага есть команда, ожидаемый результат и способ проверки.
- Задания и решения разделены, чтобы читатель мог попробовать самостоятельно.
- Примеры вывода обозначаются как примеры. Скриншоты создаются на реальном стенде.
- Гипотеза о причине ошибки не называется проверенным исправлением.
- Удаляющие команды сопровождаются объяснением, какие учебные объекты будут удалены.
