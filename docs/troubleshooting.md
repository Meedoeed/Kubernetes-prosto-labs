# Диагностика первой лабы

[К памятке](../labs/01-cluster/README.md) · [Как сообщить об ошибке](../CONTRIBUTING.md)

Ниже - рекомендации по диагностике, а не журнал подтверждённых исправлений. Сквозной прогон пока не выполнен; проверенные случаи будут добавляться с описанием окружения и результата.

Все команды относятся к учебному кластеру `k8s-first-lab`.

## Docker недоступен

**Симптом:** `docker version` не показывает раздел `Server` или сообщает, что не может подключиться к Docker daemon.

Запустите Docker Desktop либо службу Docker в Linux, затем повторите:

```bash
docker version
```

Если служба работает, но ошибка говорит об отказе в доступе, проверьте настройку доступа пользователя по документации Docker для своей ОС. Не меняйте права сокета на общедоступные.

**Проверка результата:** доступны оба раздела `Client` и `Server` без ошибки подключения.

## Кластер уже существует

```bash
kind get clusters
```

Если в списке есть `k8s-first-lab`, выберите его и проверьте состояние:

```bash
kubectl config use-context kind-k8s-first-lab
kubectl get nodes
```

Работающий кластер не нужно создавать повторно. Если предыдущая попытка завершилась ошибкой, сначала сохраните диагностику, описанную ниже.

## kubectl не подключается к API Server

```bash
docker version
kind get clusters
kubectl config current-context
```

Убедитесь, что Docker работает, кластер существует, а подключение называется `kind-k8s-first-lab`.

```bash
kubectl config use-context kind-k8s-first-lab
kubectl cluster-info
```

Если подключения с таким именем нет, проверьте, успешно ли завершилось создание кластера и выполняете ли вы команды в том же окружении - например, в том же дистрибутиве WSL. Не создавайте другой кластер наугад.

## Создание кластера завершилось ошибкой

Сохраните исходную ошибку. Если нода ещё существует, попробуйте экспортировать логи:

```bash
kind export logs --name k8s-first-lab ./kind-logs
```

Если kind уже удалил ноду после неудачи, экспорт может не сработать. В этом случае нужен текст первоначальной ошибки. Проверьте доступ Docker к интернету, свободное место и выделенные ресурсы; конкретная причина определяется по сообщению.

## Нода остаётся NotReady

```bash
kubectl get nodes
kubectl describe node k8s-first-lab-control-plane
kubectl get pods -n kube-system
```

Посмотрите `Conditions` и `Events` в описании ноды, затем состояния системных подов. Короткое ожидание сразу после создания нормально. При длительной проблеме сохраните конкретные сообщения вместо многократного повторения создания кластера.

**Проверка результата:** `kubectl get nodes` показывает `Ready`.

## Pod остаётся Pending или ContainerCreating

```bash
kubectl get pods -n default -o wide
kubectl describe pod hello-k8s -n default
```

В `Events` ищите причину задержки. Если Pod ещё не назначен ноде, сообщения планирования помогут понять причину. Если нода назначена, проверьте сообщения о загрузке образа и создании контейнера. Не всякий `Pending` означает нехватку ресурсов.

## ErrImagePull или ImagePullBackOff

```bash
kubectl describe pod hello-k8s -n default
```

Прочитайте точную ошибку в `Events`. Проверьте, что образ записан как `nginx:stable-alpine`.

- Ошибка разрешения имени указывает на проблему DNS или сети.
- Тайм-аут может быть связан с доступом к registry или proxy.
- Сообщение о лимите скачиваний требует разбираться с ограничениями registry.
- Ошибка отсутствующего образа или тега требует проверки имени.

После устранения причины kubelet повторяет попытки загрузки; повторяйте просмотр состояния. Сетевой доступ нужен именно из окружения ноды, а не только из браузера компьютера.

## AlreadyExists при kubectl run

```bash
kubectl get pods -n default
kubectl describe pod hello-k8s -n default
```

Объект с таким именем уже существует. Если он работает, продолжайте лабу. Если не работает, исследуйте состояние существующего объекта - повторный `run` его не исправляет.

## No resources found или NotFound

Проверьте выбранное подключение и namespace:

```bash
kubectl config current-context
kubectl get pods -n default
kubectl get pods -n kube-system
```

Для команд лабы нужно подключение `kind-k8s-first-lab`. Приложение находится в `default`, системные компоненты - в `kube-system`. Если Pod удалён или не был создан, отсутствие в списке ожидаемо.

## Как зафиксировать проверенное исправление

Добавляя новый случай, укажите: симптом → ОС и версии → причина → действия → результат повторного запуска → дата проверки. Пока результат не воспроизведён, помечайте его как предположение.
