# Самостоятельные задания - лаба 01

[К памятке](README.md) · [Решения для самопроверки](solutions.md)

Выполняйте задания после основной лабы, пока кластер `k8s-first-lab` и Pod `hello-k8s` существуют. Используйте команды, которые уже встречались в лабораторной. YAML, Service и сетевой доступ здесь не нужны.

## 1. Нода

Выведите список нод. Запишите имя ноды, её состояние и версию Kubernetes.

**Критерий выполнения:** можете показать, где в выводе находится каждое значение.

## 2. Компоненты Control Plane

Найдите системные поды API Server, etcd, Scheduler и Controller Manager. Запишите полные имена и кратко укажите роль каждого.

**Критерий выполнения:** найдено четыре компонента, их задачи не перепутаны.

## 3. Расположение приложения

Определите, на какой ноде работает `hello-k8s`. Найдите это значение двумя способами: в расширенном списке подов и в подробном описании Pod.

**Критерий выполнения:** оба способа показывают одну ноду.

## 4. События запуска

Найдите события, связанные с назначением ноды и запуском контейнера. Объясните, какое действие произошло на каждом этапе.

**Критерий выполнения:** вы различаете назначение ноды, получение образа, создание и запуск контейнера. Если событий уже нет, зафиксируйте это и объясните возможную причину.

## 5. Пространства имён

Сравните список системных подов и список, в котором находится `hello-k8s`. Объясните, почему они отличаются и означает ли это остановку отсутствующих в списке компонентов.

**Критерий выполнения:** в объяснении есть назначение параметра `-n` и различие `kube-system` и `default`.

## 6. Второй Pod

Создайте Pod `hello-again` с тем же образом nginx. Проверьте его состояние и определите ноду.

**Критерий выполнения:** оба учебных Pod находятся в состоянии `Running`, у каждого готовность `1/1`. Кластер по-прежнему содержит одну ноду.

## Вопросы без терминала

1. К какому компоненту обращается kubectl?
2. Кто выбирает ноду для нового Pod?
3. Кто обеспечивает запуск контейнеров на выбранной ноде?
4. Почему kubelet не виден среди подов?
5. Почему в нашем стенде приложение работает на ноде с ролью `control-plane`?

После проверки можно оставить стенд для дальнейшей практики или удалить учебный кластер командой из [памятки](README.md#завершение).
